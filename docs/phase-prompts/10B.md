# Fase 10B: guardrail — classificador de injeção por LLM

Você vai implementar a PARTE 10B da Fase 10 do docs/SPEC.md (leia a seção "Phase 10": decisões e item 10B). Faça SOMENTE o que está listado aqui. Esta fase NÃO chama nenhum modelo real: os testes usam modelos roteirizados. A medição com modelo real é a 10C.

Contexto: a 10A deixou os padrões como primeira barreira barata e mediu que eles bloqueiam 6 de 20 tentativas de injeção ou ataque (as paráfrases passam). Agora entra a segunda barreira: um classificador por LLM, com o prompt já pré-registrado em `src/prompts/guardrail_classifier.md`, que avalia o que passou pelos padrões. A saída é estruturada: o modelo é obrigado a chamar a função `GuardrailVerdict` (sem texto livre). Decisão registrada no SPEC: **fail-open** por padrão (erro ou timeout do classificador deixa a mensagem seguir para o supervisor); `fail-closed` é configurável e responde 503. Erro de configuração (sem chave, modelo inexistente, autenticação) NÃO é falha do classificador: propaga como hoje (503).

Desenho do grafo depois desta fase:

```
START → guardrail (máscara + padrões) → handoff_gate → guardrail_classifier → supervisor ⇄ tools → abstention_check → END
            └─ bloqueado → END           └─ chamado pendente → END   └─ block → END
```

O classificador fica DEPOIS do `handoff_gate` de propósito: mensagens enviadas enquanto um chamado espera o atendente não chegam ao modelo, então não precisam do classificador (e continuam funcionando sem chave).

4. Novo `src/agents/injection_classifier.py` (sem `re`):
   ```python
   class GuardrailVerdict(BaseModel):
       """Verdict on one merchant message (see src/prompts/guardrail_classifier.md)."""
       verdict: Literal["block", "allow"]
       category: Literal["prompt_injection", "prompt_leak", "attack_request", "none"]

   @dataclass(frozen=True)
   class ClassifierResult:
       status: str            # "ok" | "error"
       verdict: str | None    # "block" | "allow" | None (error)
       category: str | None
       error_type: str | None # None when ok
       latency_ms: float
       usage: dict[str, int] | None   # input_tokens, output_tokens, total_tokens
       model: str | None
       def as_metadata(self) -> dict[str, Any]:
           """{"status", "verdict", "category", "error_type", "latency_ms", "model"} (no usage)."""

   PROMPT_PATH = Path(__file__).resolve().parent.parent / "prompts" / "guardrail_classifier.md"
   def load_classifier_prompt() -> str  # PROMPT_PATH.read_text(encoding="utf-8").strip()
   def format_classifier_input(text: str) -> str
   class InjectionClassifier:
       def __init__(self, model: BaseChatModel | None = None) -> None
       def classify(self, text: str) -> ClassifierResult
   ```
   - `format_classifier_input(text)` = `"<message>\n" + text.replace("<", "&lt;").replace(">", "&gt;") + "\n</message>"` (a mensagem não consegue fechar a tag).
   - O modelo é preparado na PRIMEIRA chamada de `classify` (não no `__init__`): se `model` foi passado, usa-o; senão `get_chat_model(settings.GUARDRAIL_CLASSIFIER_MODEL or None, timeout_s=settings.GUARDRAIL_CLASSIFIER_TIMEOUT_S, max_retries=0)`. Depois `bind_tools([GuardrailVerdict], tool_choice="GuardrailVerdict")`. Guarde o modelo ligado para as chamadas seguintes.
   - `classify` invoca com `[SystemMessage(content=load_classifier_prompt()), HumanMessage(content=format_classifier_input(text))]` e mede a latência (ms, 2 casas). Resultado:
     - `LLMNotConfiguredError` e `LLMConfigurationError` (inclusive se levantados ao preparar o modelo) → relançados sem alteração.
     - `ModelNotFoundError`, `ModelAuthenticationError`, `ModelPermissionDeniedError`, `ModelInvalidRequestError` (de `langchain_core.exceptions`) → `raise LLMConfigurationError(type(exc).__name__) from exc`.
     - qualquer outra exceção → `ClassifierResult(status="error", verdict=None, category=None, error_type=type(exc).__name__, ...)`.
     - resposta sem chamada a `GuardrailVerdict`, com argumentos inválidos para o modelo pydantic, ou incoerente (`verdict == "allow"` precisa ter `category == "none"` e vice-versa) → `status="error"`, `error_type="unparseable"`.
     - caso contrário → `status="ok"` com `verdict` e `category`.
     - `usage` vem de `usage_metadata` da resposta (quando houver; senão None); `model` = `extract_model_name(<modelo usado>)`.
   - Nenhum log neste módulo.
