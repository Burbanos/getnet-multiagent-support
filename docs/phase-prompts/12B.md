## Passo 1 — `src/rag/lexical.py` (BM25 sem dependência nova)

```python
def fold(text: str) -> str: ...
def tokenize(text: str) -> list[str]: ...
class BM25Index:
    def __init__(self, documents: list[str], k1: float = 1.2, b: float = 0.75) -> None: ...
    def scores(self, query: str) -> list[float]: ...
    def top(self, query: str, k: int) -> list[tuple[int, float]]: ...
```

- `fold`: `unicodedata.normalize("NFKD", text)`, descarta os caracteres com `unicodedata.combining(c)`, `lower()`, e troca todo
  caractere que não é `isalnum()` por um espaço. `tokenize(text) = fold(text).split()`.
- `BM25Index`: `N` documentos, `avgdl` = média dos comprimentos (em tokens), `df(t)` = número de documentos com o termo.
  `idf(t) = math.log(1 + (N - df + 0.5) / (df + 0.5))`. Para uma consulta, os termos são os tokens únicos na ordem em que
  aparecem (`list(dict.fromkeys(tokenize(query)))`) e
  `score(d) = math.fsum(idf(t) * tf * (k1 + 1) / (tf + k1 * (1 - b + b * len(d) / avgdl)))` sobre os termos com `tf > 0` no
  documento. `scores` devolve um valor por documento, na ordem dos documentos. `top` devolve os pares `(índice, score)` com
  `score > 0`, ordenados por `(-score, índice)`, no máximo `k`. Lista vazia de documentos → `scores` e `top` vazios.

## Passo 2 — `src/rag/reranker.py`

Siga a estrutura de `src/agents/injection_classifier.py` (mesmo tratamento de exceções e de configuração).

```python
PROMPT_PATH = <src/prompts/reranker.md>

class PassageRelevance(BaseModel):
    index: int
    relevance: int = Field(ge=0, le=3)

class RerankVerdict(BaseModel):
    """Relevance of each passage to the merchant's question (see src/prompts/reranker.md)."""
    scores: list[PassageRelevance]

@dataclass(frozen=True)
class RerankResult:
    status: str                    # "ok" | "invalid" | "error"
    relevance: list[int] | None    # one value per passage, in passage order; None unless ok
    error_type: str | None         # None when ok
    latency_ms: float
    usage: dict[str, int] | None   # exactly input_tokens, output_tokens, total_tokens (ints) or None
    model: str | None
    def as_metadata(self) -> dict[str, Any]: ...   # {"status", "error_type", "latency_ms", "model"}

def load_reranker_prompt() -> str: ...             # PROMPT_PATH lido em UTF-8, .strip()
def format_rerank_input(query: str, passages: list[dict[str, Any]]) -> str: ...
class LLMReranker:
    def __init__(self, model: BaseChatModel | None = None) -> None: ...
    def rerank(self, query: str, passages: list[dict[str, Any]]) -> RerankResult: ...
```

- `format_rerank_input`: `esc(s) = s.replace("<", "&lt;").replace(">", "&gt;")`; as partes, unidas por `"\n"`:
  `"<query>"`, `esc(query)`, `"</query>"` e, para cada passagem `i` (a partir de 0), `f'<passage index="{i}">'`,
  `esc(passage["title"])`, `esc(passage["text"])`, `"</passage>"`.
- Modelo: o injetado ou, de forma preguiçosa, `get_chat_model(settings.RAG_RERANK_MODEL or None,
  timeout_s=settings.RAG_RERANK_TIMEOUT_S, max_retries=0)` ligado com `bind_tools([RerankVerdict], tool_choice="RerankVerdict")`.
  Mensagens: `SystemMessage(load_reranker_prompt())` e `HumanMessage(format_rerank_input(...))`. Sem modelo reserva.
- Lista de passagens vazia → `RerankResult("ok", [], None, 0.0, None, None)` sem chamar o modelo.
- `LLMNotConfiguredError` e `LLMConfigurationError` (e as exceções de configuração do LangChain, como no classificador) se
  propagam. Qualquer outra exceção → `status="error"`, `error_type` = nome da classe, `relevance=None`, `usage=None`.
- Resposta sem chamada `RerankVerdict` → `invalid`, `no_verdict_call`; argumentos que falham o schema → `invalid`,
  `invalid_arguments`; índices que não são exatamente `0..n-1`, cada um uma vez → `invalid`, `bad_indexes`. Nos casos
  `invalid`, `usage` vem da resposta (normalizada).
- `ok`: `relevance[i]` = nota da passagem `i`. `usage` = `{"input_tokens", "output_tokens", "total_tokens"}` lidos do
  `usage_metadata` da resposta (`total_tokens` = soma se faltar), ou `None` sem `usage_metadata`. `model` =
  `extract_model_name(modelo)`.

## Passo 3 — `VectorIndex.scores` e o `Retriever` híbrido

Em `src/rag/index.py`, acrescente `VectorIndex.scores(vector) -> np.ndarray`: a similaridade de cosseno com todos os trechos,
na ordem de `self.chunks`, com a mesma normalização do vetor que `search` já faz. `search` não muda.

Em `src/rag/retriever.py`, o construtor passa a ser
`Retriever(index, embedder, min_score, top_k, lexical=None, reranker=None, dense_candidates=6, lexical_candidates=6,
min_relevance=2, rrf_k=60)` e `search(query, include_candidates=False)`. Com `reranker is None`, `search` faz exatamente o que faz
hoje (regra 3) e ignora `include_candidates`. Com reranker:

1. `vec = embedder.embed_query(query)`; `s = index.scores(vec)`; `dense_order = np.argsort(-s, kind="stable")`;
   `dense_rank[i]` = posição de `i` em `dense_order`, a partir de 1.
2. Portão: sem trechos, ou `s[dense_order[0]] < min_score` → `abstain` com `reason: "below_threshold"`, sem chamar o reranker.
3. Candidatos: `D` = os `dense_candidates` primeiros de `dense_order`; `L` = os índices de `lexical.top(query,
   lexical_candidates)` (se `lexical is None`, construa e guarde um `BM25Index` com `chunk["title"] + "\n" + chunk["text"]` de
   cada trecho do índice, na ordem do índice). Fusão: `fused[i] = math.fsum(1 / (rrf_k + r))` sobre as listas `D` e `L` em que
   `i` aparece, com `r` = posição de `i` naquela lista a partir de 1. Os candidatos (união de `D` e `L`, sem repetição) ficam
   em ordem de `(-fused[i], dense_rank[i], i)`.
4. `res = reranker.rerank(query, [{"title": c["title"], "text": c["text"]} ...])` na ordem dos candidatos.
5. `res.status == "ok"`: mantenha os candidatos com `relevance >= min_relevance`, ordenados por `(-relevance, posição na
   ordem fundida)`, no máximo `top_k`. Nenhum → `abstain` com `reason: "no_passage_answers"`. Senão `success`.
6. `res.status` diferente de `ok`: resultado da regra densa de hoje (os `top_k` primeiros de `dense_order` com score
   `>= min_score`), status `success` (o portão já garantiu ao menos um).
7. Cada documento tem as chaves de hoje (`url`, `title`, `fetched_at`, `market`, `chunk_id`, `score` = cosseno denso como
   `float`, `text`) e mais `dense_rank` (int), `lexical_rank` (posição em `L` a partir de 1, ou `None`) e `relevance` (int, ou
   `None` no caso 6).
8. O resultado tem as chaves de hoje (`status`, `query`, `documents`, `min_score`), `reason` (só em `abstain`) e `retrieval`:
   `{"mode": "hybrid", "candidates": <número de candidatos, 0 no portão>, "rerank": None no portão, senão
   {**res.as_metadata(), "kept": <número de documentos mantidos pelo reranker, ou None no caso 6>}, "usage": res.usage ou None}`.
   Com `include_candidates=True`, `retrieval` ganha também `"candidate_list"`: lista, na ordem fundida, de
   `{"chunk_id", "dense_score", "dense_rank", "lexical_rank"}`, e `"relevance"`: `res.relevance` (ou `None`); no portão as duas
   são `[]` e `None`.
9. Um registro de log `rerank finished` (logger `multiagent.rag.retriever`) com `status` e `latency_ms` em `extra`, sem
   consulta nem texto de passagem. No portão, nenhum registro.

`get_knowledge_retriever()`: quando `settings.RAG_RERANK_ENABLED`, passa `lexical` (o `BM25Index` do índice), `reranker=
LLMReranker()` e os parâmetros das configurações; senão, como hoje.

## Passo 5 — `src/rag/hybrid_eval.py` (medição sobre as 48 consultas do 3D)

Constantes: `DATASET = "data/eval/retrieval_labeled.jsonl"`, `EMB_NPY = "data/eval/retrieval_query_embeddings.npy"`,
`EMB_META = "data/eval/retrieval_query_embeddings.json"`, `RUNS_DIR = "reports/retrieval_runs"`.

- `load_inputs() -> tuple[records, qvecs, index]`: `load_labeled` e `dataset_sha256` de `src/rag/calibration.py`, as mesmas
  validações de `run_report` (ids, sha do conjunto, modelo, dimensão; `ValueError` se não baterem) e o índice de
  `settings.INDEX_DIR`.
- `build_retriever(index, vector, reranker) -> Retriever`: `Retriever` com um embedder que devolve `vector` em `embed_query`,
  `min_score=settings.RAG_MIN_SCORE`, `top_k=settings.RAG_TOP_K`, um único `BM25Index` do índice reaproveitado entre consultas,
  `reranker` e os demais parâmetros das configurações. É o mesmo código de produção, sem chamada de embedding.
- `run_hybrid(run_id, runs_dir=RUNS_DIR, reranker=None, sleep_s=0.0, max_consecutive_errors=3) -> dict`: `reranker=None` →
  `LLMReranker()`. Arquivo `<runs_dir>/<run_id>.jsonl`, uma linha por consulta, na ordem do conjunto, `flush` a cada linha.
  O arquivo só é criado ao gravar a primeira linha (sem chave, nada é criado). Retomável: pula ids cuja última linha tem
  `rerank_status` em `ok`, `invalid` ou `gated`; um id com `error` é tentado de novo.
  Para depois de `max_consecutive_errors` registros `error` seguidos. Pausa `sleep_s` só depois de uma chamada ao reranker.
  `LLMNotConfiguredError`/`LLMConfigurationError` se propagam. Cada linha, exatamente com estas chaves:
  `id`, `run_id`, `timestamp` (ISO UTC), `status` (`success`/`abstain`), `reason` (ou `None`), `documents` (lista de
  `chunk_id`), `candidates` (o `candidate_list`), `relevance`, `rerank_status` (`gated` no portão, senão o status do
  reranker), `error_type`, `latency_ms`, `model` (os três do reranker, ou `None` no portão) e `usage`. Nenhum texto de consulta
  ou de passagem. Devolve `{"attempted", "ok", "invalid", "errors", "gated", "skipped", "stopped_early"}`.
- `dense_baseline(records, qvecs, index) -> dict[id, list[chunk_id]]`: a regra densa de hoje (vazia se a melhor for menor que
  `RAG_MIN_SCORE`; senão os `RAG_TOP_K` primeiros com score `>= RAG_MIN_SCORE`), com `np.argsort(-s, kind="stable")`.
- `metrics(records_labeled, documents_by_id, chunks_by_id) -> dict`, com exatamente estas chaves (as respondíveis são as 30
  `answerable`; uma consulta "responde" quando tem ao menos um documento):
  `answer_rate`, `hit@1`, `hit@3`, `mrr`, `answer_hit@3`, `off_topic_abstain_rate`, `uncovered_abstain_rate` e
  `answer_chunk_rank`. `hit@k`: o primeiro documento cuja `doc_url` está em `gold_urls` está na posição `<= k`. `mrr`: média de
  `1/posição` desse documento (0 se não houver). `answer_hit@3`: um dos 3 primeiros documentos tem `doc_url` em `gold_urls` e
  contém um `gold_snippet` (com `normalize_text` de `calibration.py` dos dois lados). `answer_chunk_rank`: `{id: posição do
  primeiro documento que satisfaz a condição do answer_hit, ou None}` para as respondíveis. Taxas = contagem / tamanho da
  categoria. Médias com `math.fsum`.
- `hybrid_report(run_ids, runs_dir=RUNS_DIR, out_json="reports/retrieval_hybrid.json", out_md="reports/retrieval_hybrid.md")
  -> dict` (devolve o mesmo dict que grava). JSON com exatamente as chaves `dataset`, `dataset_sha256`, `index_chunks`, `settings` (`min_score`, `top_k`,
  `dense_candidates`, `lexical_candidates`, `min_relevance`, `rrf_k`), `dense` (`metrics` da linha de base), `runs` e `summary`.
  `runs[run_id]` = `complete` (48 linhas e nenhuma com `error`), `counts` (`ok`, `invalid`, `errors`, `gated`), `model`
  (o primeiro não nulo), `metrics` (sobre os `documents` registrados; consulta sem linha conta como abstenção),
  `rerank_latency_p50_ms` e `rerank_latency_p95_ms` (posto mais próximo, sobre `ok` e `invalid`), `tokens_mean_per_call`
  (`input_tokens`, `output_tokens`: média sobre as linhas com `usage`) e `cost_usd_per_call` (`cost_usd` de
  `src/core/pricing.py` com o modelo e as médias; `None` se não houver). `summary[m]` = `{"mean", "min", "max"}` de cada métrica
  numérica sobre as execuções (`answer_chunk_rank` fica de fora). O Markdown, em pt-BR, tem uma tabela com uma linha por
  métrica e as colunas "Denso (regra atual)", cada execução e a média; uma tabela por consulta (id, categoria, decisão densa,
  decisão em cada execução); e as posições do trecho com a resposta das respondíveis que mudaram entre o denso e a média.
- CLI `python -m src.rag.hybrid_eval run --run-id ID [--sleep S]` e `python -m src.rag.hybrid_eval report --runs
  ID1,ID2,ID3`. Sem chave: mensagem citando `GEMINI_API_KEY` e saída 2. `report` com execução inexistente: saída 1, nada
  gravado.

Não crie nenhum arquivo em `reports/retrieval_runs/` nem `reports/retrieval_hybrid.*`: as execuções são do autor.
