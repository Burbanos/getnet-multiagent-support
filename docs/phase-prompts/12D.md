## Passo 3 — `src/agents/answer_check.py` (funções puras, sem modelo)

```python
URL_TRAILING = ")]}>.,;:!?\"'*`"
TICKET_PREFIX = "GET-TKT-"
PROMISE_PHRASES = (
    "em breve", "em instantes", "logo mais", "em alguns minutos", "em poucos minutos", "em ate", "dentro de",
    "prazo de", "nas proximas", "shortly", "soon", "within", "in a few", "in the next", "as soon as",
)
def extract_urls(text: str) -> list[str]: ...
def extract_ticket_ids(text: str) -> list[str]: ...
def find_promises(text: str) -> list[str]: ...
def check_answer(answer: str, evidence: str, ticket_ids: set[str], ticket_turn: bool) -> dict[str, list[str]]: ...
```

- `extract_urls`: para cada token de `text.split()`, procure `"https://"` e, se não houver, `"http://"`; a partir dele, separe
  por `"]("` (link Markdown `[url](url)`) e, para cada parte que começa com `http`, remova do fim, repetidamente, os caracteres
  de `URL_TRAILING`; guarde se tiver mais de 8 caracteres. Sem repetição, na ordem em que aparecem.
- `extract_ticket_ids`: cada ocorrência de `GET-TKT-` seguida de letras, dígitos e `-` (o `-` final é removido), sem repetição.
- `find_promises`: `fold` de `src/rag/lexical.py`, espaços normalizados, e devolve as frases de `PROMISE_PHRASES` (na ordem da
  tupla) que aparecem como palavras inteiras (`f" {frase} "` dentro de `" " + texto + " "`).
- `check_answer`: devolve só as checagens que falharam, nesta ordem de chaves: `urls` (URLs cujo `unquote(url).lower()` sem `/`
  final não está em `unquote(evidence).lower()`), `ticket_ids` (ids fora de `ticket_ids` e ausentes de `evidence`) e, só quando
  `ticket_turn`, `time_promise` (o resultado de `find_promises`). Tudo certo → `{}`.

O revisor já rodou essas regras nas 234 respostas commitadas da v2: nenhuma falha. O verificador confere de novo, com o seu código.

## Passo 4 — Nó `answer_check` no grafo (`src/core/graph.py`)

- Constantes, exatamente:

```python
ACCOUNT_GUARDRAIL_UNAVAILABLE = (
    "Os dados da conta estão indisponíveis agora porque a verificação de segurança não pôde ser feita. "
    "Peça ao lojista para tentar de novo mais tarde. / Account data is unavailable right now because the safety check "

ANSWER_CHECK_FALLBACK = (
    "Não consegui confirmar esta resposta nas fontes consultadas, então prefiro não enviá-la. Posso encaminhar seu pedido "
    "a um atendente humano, se quiser. / I could not confirm this answer against the sources I checked, so I would rather "
    "not send it. I can forward your request to a human agent if you want."
)
ANSWER_REVISION_INSTRUCTION = (
    "[Automatic check before sending] Your last answer failed these checks: {failures}. Write the final answer to the "
    "merchant again, in the same language, keeping everything that passed and fixing only that: cite only URLs that "
    "appear in tool results of this conversation, mention only ticket ids that a tool returned, and do not promise when "
    "anyone will reply or act. Do not call tools. Reply with the answer text only."
)
```

- Fiação: a saída `"end"` de `_supervisor_condition` passa a ir para o novo nó `answer_check`, e `answer_check →
  abstention_check`. O resto do grafo não muda (portão, escalonamento forçado e retomada pelo operador seguem como estão; a
  retomada passa pelo `answer_check` porque termina no supervisor).
- `_answer_check_node(state)`:
  1. Última mensagem: `AIMessage` sem `tool_calls` e com texto (`_get_message_text`). Sem texto, ou `ANSWER_CHECK_ENABLED`
     falso → `answer_check = {"status": "skipped", "failed": [], "revision_failed": None, "revision_error": None}`.
  2. `evidence` = o texto de todas as `ToolMessage` da thread, mais o das `HumanMessage` com `additional_kwargs["origin"] ==
     "operator"`, unidos por `"\n"`. `ticket_ids` = o `ticket_id` do `state["ticket"]` (se houver) e o `pending_ticket_id` (se
     houver). `ticket_turn = bool(state.get("ticket"))`.
  3. `check_answer(...)` vazio → `status: "passed"` (mesmo formato), sem chamar modelo.
  4. Falhou → uma revisão: os modelos já ligados do supervisor (`_get_bound_models`) via `invoke_model_with_fallback`, com
     `[SystemMessage(load_supervisor_prompt())] + mensagens da thread + [HumanMessage(ANSWER_REVISION_INSTRUCTION.format(
     failures=...))]`, onde `failures = "; ".join(f"{chave}: {', '.join(valores)}")` na ordem de `check_answer`. A instrução
     nunca é gravada na thread. Tokens da revisão somados a `SupervisorAgent` (e ao total). Se a revisão tem texto, sem
     `tool_calls`, e passa no `check_answer` → `status: "revised"`, o texto revisado. Se falha de novo → `status: "fallback"`,
     `revision_failed` = as chaves que falharam; sem texto ou com `tool_calls` → `revision_failed: ["empty_or_tool_call"]`;
     exceção na revisão → `revision_error` = nome da classe (`LLMNotConfiguredError`/`LLMConfigurationError` se propagam). Em
     `fallback`, o texto final é `ANSWER_CHECK_FALLBACK`. `failed` = as chaves da primeira checagem.
  5. Quando o texto muda, devolva `messages: [AIMessage(content=novo, id=<id da última mensagem>)]` (substitui, não acrescenta),
     `final_response` e `answer_check`. Sempre `metrics.inc_answer_check(status)` e um log `answer check` com `status` e
     `failed` em `extra`, sem texto.

## Passo 6 — Classificador nos resultados de `search_web`

- `src/agents/injection_classifier.py`: `WEB_PROMPT_PATH` (o `src/prompts/guardrail_web_classifier.md`);
  `load_classifier_prompt(path=None)` lê `path or PROMPT_PATH`; `InjectionClassifier(model=None, prompt_path=None)` guarda
  `self.prompt_path` (público) e usa esse prompt no `classify`. Com `prompt_path=None`, nada muda.
- `SpecialistAgent` ganha o parâmetro `web_classifier=None`. Depois de executar `search_web` e antes de criar a `ToolMessage`,
  quando `web_classifier` não é `None` e `GUARDRAIL_WEB_RESULTS_ENABLED`: se a saída tem `status == "success"` e `results` não
  vazio, monte `"\n\n".join(f"[{i}] {title}\n{snippet}\n{url}")` (a partir de 1) e chame `web_classifier.classify(texto)`.
  `ok` com `allow` → segue como hoje, `metrics.inc_guardrail("web_allow")`. Qualquer outro desfecho (`block`, `invalid`,
  `error`) → a saída vira `{"status": "blocked", "error": "web_results_blocked", "results": []}` antes de a `ToolMessage` ser
  criada (o modelo nunca vê os resultados; nada vai para `web_results` nem `sources`) e `metrics.inc_guardrail("web_block")`
  ou, em `error`, `"web_unavailable"`. Em todos os casos, acrescente a `web_guardrail` do especialista
  `{**resultado.as_metadata(), "results": <quantidade>, "dropped": <bool>}` e some os tokens do classificador ao uso do
  especialista. O retorno do especialista ganha `web_guardrail` (lista). Log `web results screened` com `status` e `dropped`.
- `OrchestrationGraph.__init__`: o Knowledge Agent recebe `web_classifier` pela mesma regra do classificador de mensagens:
  `InjectionClassifier(guardrail_model, prompt_path=WEB_PROMPT_PATH)` quando há `guardrail_model`;
  `InjectionClassifier(prompt_path=WEB_PROMPT_PATH)` quando não há `chat_model` (produção); senão `None` (os testes atuais não
  mudam). O Support Agent não recebe. `_tools_node` junta o `web_guardrail` do especialista ao do estado.
