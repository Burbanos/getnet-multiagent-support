# Fase 15E — Publicação e checagem da matriz

**Modelo:** Antigravity, modo Orchestrator (Neon). **Base:** `3426c78` (rodada 2 commitada).
**Contrato:** `docs/SPEC.md`, seção 3.8 (leia inteira) e, para contexto, o bloco "Round 2 result" da seção 3.4.
**Verificador:** `python scripts/verify_phase15e.py`.

Esta fase não muda código, testes, dados nem relatórios. O texto do README foi escrito pelo revisor a partir dos registros
commitados e está em `docs/phase-prompts/15E_README.md`.

Os arquivos do revisor já estão na pasta: `docs/SPEC.md`, este prompt, `docs/phase-prompts/15E_README.md` e
`scripts/verify_phase15e.py`. **Não altere nenhum deles.** Se algo neles parecer errado (um número, um caminho, uma
afirmação que o código não sustenta), não corrija: registre em "Perguntas / divergências" do `docs/STATUS.md` e siga.

## Regras contra atalhos

- Só podem mudar: `README.md`, `docs/STATUS.md` e a remoção dos arquivos listados abaixo. Nada em `src/`, `tests/`, `data/`,
  `reports/`, `deploy/`, `scripts/` (fora a remoção), nem nos outros arquivos de `docs/`.
- O README é cópia exata do rascunho: nenhuma palavra, espaço ou quebra de linha a mais ou a menos.
- Nenhuma execução com modelo real e nenhum comando que grave em `reports/` ou `data/`.

## O que fazer

1. Confira que a base é o `3426c78` (`git log -1 --oneline`) e que as únicas mudanças na pasta são os quatro arquivos do
   revisor (`git status`).
2. Copie o rascunho para o README, byte a byte, e remova o rascunho:
   ```powershell
   Copy-Item -Force docs/phase-prompts/15E_README.md README.md
   Remove-Item docs/phase-prompts/15E_README.md
   ```
3. Aposente os arquivos da fase anterior: `git rm docs/phase-prompts/15D.md scripts/verify_phase15d.py`.
4. Rode `python scripts/verify_phase15e.py`. Ele roda de novo o verificador da 15D a partir do `5ad0b92` (que roda os da
   15C e da 15B, com o `pytest` completo) e recalcula a matriz a partir dos registros; leva vários minutos. Se o sandbox
   travar o `pytest`, peça ao usuário para rodar o comando no terminal e colar a saída.
5. Reescreva `docs/STATUS.md` (pt-BR, no máximo 80 linhas):
   - subfase 15E, base `3426c78`, o que mudou (README copiado do rascunho; 15D aposentada);
   - a saída do verificador: só as linhas `PASS`, `FAIL` e `INFO` e a linha `SUMMARY:`, num bloco de texto. Não cole as
     linhas de log em JSON que os testes imprimem (as que começam com `{`);
   - a seção "Perguntas / divergências" (escreva "nenhuma" se não houver).
6. Rode o verificador de novo (a checagem `S1.status` lê o `docs/STATUS.md`). Todas as checagens devem passar; se alguma
   falhar, não contorne: registre em "Perguntas / divergências" e pare antes do commit.
7. Um único commit, com os arquivos do revisor sem alteração:
   `phase-15e: README with both rounds of Phase 15 and the requirements matrix check`.
