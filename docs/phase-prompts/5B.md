3. `src/core/graph.py`, constantes no nível do módulo, exatamente:
   ```python
   HANDOFF_PENDING_MESSAGE = (
       "Seu chamado {ticket_id} está com a equipe de atendimento humano. A resposta aparecerá nesta conversa quando for registrada. / "
       "Your request {ticket_id} is with our human support team. The reply will appear in this conversation when it is recorded."
   )
   HANDOFF_REPLY_PREFIX = "Resposta da equipe de atendimento humano (chamado {ticket_id}) / Reply from our human support team (request {ticket_id}):\n\n"
   ```

4. `src/core/graph.py`, estado pendente:
   - Ao criar um ticket com sucesso (nó de tools e escalonamento forçado), devolva também `"pending_ticket_id": <ticket_id>`. Ticket que falhou não muda `pending_ticket_id`.
   - Em `run_sync`, coloque `"handoff": None` no estado de entrada de cada turno e NÃO coloque `pending_ticket_id` (ele precisa sobreviver entre turnos e reinícios pelo checkpointer). Passe `handoff=result.get("handoff")` para o `AgentState`.

5. `src/core/graph.py`, nó `handoff_gate` ligado assim: START → `guardrail` → (bloqueado → END) → `handoff_gate` → `supervisor` ou END. O guardrail continua ANTES do portão (a mensagem do cliente é sempre mascarada). Com `pending_ticket_id` vazio, o portão não faz nada e segue para o supervisor. Com ticket pendente, leia o ticket com `get_tickets_repository().get_ticket(...)`:
   - ticket inexistente → limpa `pending_ticket_id` e segue para o supervisor;
   - tem `operator_reply` e `delivered_at` vazio (respondido, ou respondido e depois fechado) → resposta `HANDOFF_REPLY_PREFIX.format(ticket_id=...) + operator_reply` como `AIMessage` e `final_response`, chama `mark_delivered`, limpa `pending_ticket_id`, `handoff = {"ticket_id": ..., "status": "delivered"}`, `agents_used = ["HumanHandoff"]`, vai para END;
   - fechado sem resposta → limpa `pending_ticket_id`, `handoff = {"ticket_id": ..., "status": "resumed"}` e segue para o supervisor (atendimento normal);
   - caso contrário (open ou in_progress) → `HANDOFF_PENDING_MESSAGE.format(ticket_id=...)` como `AIMessage` e `final_response`, `handoff = {"ticket_id": ..., "status": "pending"}`, `agents_used = ["HumanHandoff"]`, vai para END.
   Nos turnos que terminam no portão, o LLM NÃO é chamado (`llm_model` e `tokens` ficam `None`).

6. `src/main.py`: `AgentMetadata` ganha `handoff: dict[str, Any] | None`; preencha com `state.handoff` e use `agent_type = "HumanHandoff"` quando `handoff.status` for `pending` ou `delivered` (senão `"SupervisorAgent"`). Troque `HTTP_422_UNPROCESSABLE_ENTITY` por `HTTP_422_UNPROCESSABLE_CONTENT` (aviso de depreciação).
