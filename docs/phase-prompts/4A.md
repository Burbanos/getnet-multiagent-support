## Passos

1. Crie `src/core/auth.py`:
   - `ROLES = ("customer", "operator")`; `@dataclass(frozen=True) class Principal` com `user_id: str`, `role: str`, `key_id: str` (`key_id` = 12 primeiros caracteres do hash; é o único valor derivado da chave que pode ir para log).
   - `hash_api_key(key: str) -> str`: sha256 hex da chave em UTF-8.
   - `parse_api_keys(spec: str) -> dict[str, Principal]` (chave do dict = hash): entradas separadas por `;` (ignore espaços e entradas vazias), cada uma `hash:user_id:role` com exatamente 3 partes. `ValueError` se o hash não tiver 64 caracteres hex minúsculos, `user_id` vazio, papel fora de `ROLES` ou hash repetido.
   - `DEV_API_KEYS = {"getnet-dev-key": ("cliente1988", "customer"), "getnet-dev-operator": ("operador_dev", "operator")}` e `auth_mode() -> str`: `"configured"` se `settings.API_KEYS` não está vazio; senão `"none"` se `settings.APP_ENV.lower() == "production"`; senão `"development_defaults"`.
   - `get_principal_table() -> dict[str, Principal]`, lendo `settings` a cada chamada: `configured` → `parse_api_keys(settings.API_KEYS)`; `none` → `{}`; `development_defaults` → as duas chaves de desenvolvimento (com hash).
   - `RateLimiter(limit_per_minute: int, clock=time.monotonic)` com atributo público `clock` e `hit(key_id) -> float | None`: janela deslizante de 60 s por `key_id`; devolve os segundos até liberar quando o limite foi atingido, senão registra e devolve `None`. `limit_per_minute <= 0` desliga (sempre `None`). `get_rate_limiter()` devolve a instância única criada com `settings.RATE_LIMIT_PER_MINUTE`; `reset_rate_limiter()` descarta a instância.
   - `authenticate(x_api_key: str | None = Header(None, alias="X-API-Key")) -> Principal`: compara o hash da chave recebida com cada hash da tabela usando `hmac.compare_digest`; ausente ou desconhecida → `HTTPException(401, "Missing or invalid API key.")` (nunca repita a chave na resposta nem no log). Depois chama `get_rate_limiter().hit(principal.key_id)`; se devolver tempo → `HTTPException(429, ..., headers={"Retry-After": str(max(1, math.ceil(espera)))})`.
   - CLI `python -m src.core.auth hash`: lê a chave com `getpass.getpass()` e imprime só o hash.

3. `src/main.py`:
   - Apague `verify_api_key`. `/chat`, `/api/v1/chat`, `/tickets` e `/tickets/{ticket_id}` recebem `principal: Principal = Depends(authenticate)`.
   - `ChatRequest`: `user_id: str | None = None` (sem default de usuário; tire também do exemplo do schema); `session_id: str | None = Field(default=None, min_length=1, max_length=64)`.
   - `/chat`: se `payload.user_id` vier e for diferente de `principal.user_id` → 403 "user_id does not match the authenticated credential.". Chame o orquestrador com `user_id=principal.user_id` e `session_id=payload.session_id or uuid.uuid4().hex`. `ChatResponse.user_id` e os logs usam `principal.user_id`. O tratamento de erros (503, 500 com `X-Trace-Id`) continua igual.
   - `/tickets`: novo parâmetro de query `user_id: str | None = None`. Cliente (`customer`): se `user_id` vier diferente do dele → 403; sempre lista só os dele. Operador: lista todos ou filtra por `user_id`.
   - `/tickets/{ticket_id}`: cliente que não é dono recebe 404 (a mesma resposta de ticket inexistente); operador vê qualquer um.
   - `/health` continua público e ganha o campo `auth_mode` (de `auth_mode()`).
