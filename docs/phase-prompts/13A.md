## Passo 4 — Rate limit compartilhado (Redis)

**`src/core/rate_limit.py`** (novo):
- mova para cá a classe `RateLimiter` de `auth.py` sem mudar o comportamento; `auth.py` a reexporta
  (`from src.core.rate_limit import RateLimiter, RedisRateLimiter`), para `auth.RateLimiter` continuar existindo.
- `RedisRateLimiter(client, limit_per_minute: int, *, prefix: str = "getnet:rl:", clock: Callable[[], float] = time.time)`
  com `hit(key_id) -> float | None` (mesmo contrato do `RateLimiter`: `None` = permitido; senão segundos até poder, entre 0
  e 60; `limit_per_minute <= 0` desliga). Janela deslizante de 60 s num sorted set `prefix + key_id`, numa pipeline
  `transaction=True`: remove os membros com score < agora−60 000 ms, adiciona um membro único com score = agora em ms, lê o
  `ZCARD` e o membro mais antigo, renova o `PEXPIRE` (61 000 ms). Se o total passar do limite, remove o membro que acabou de
  adicionar (requisição recusada não conta) e devolve o tempo até o mais antigo sair da janela.
- Falha do Redis (`redis.exceptions.RedisError` ou `OSError`): usa um `RateLimiter` em memória interno, incrementa a métrica
  nova `getnet_rate_limit_backend_errors_total` (em `metrics.py`, no `render()`), loga um aviso sem a chave nem o texto do erro
  e, por 5 s, não tenta o Redis de novo. Atributo `degraded: bool` e propriedade `backend` (`"redis"` ou `"redis_degraded"`).
- `rate_limit_backend() -> str` para o `/health`: `"memory"` sem `REDIS_URL`, senão o `backend` do limitador ativo.
- `get_rate_limiter()` (em `auth.py`): com `REDIS_URL`, `RedisRateLimiter(redis.Redis.from_url(settings.REDIS_URL,
  socket_timeout=0.5, socket_connect_timeout=0.5), settings.RATE_LIMIT_PER_MINUTE, prefix=settings.RATE_LIMIT_REDIS_PREFIX)`;
  sem, o `RateLimiter` de hoje.

## Passo 5 — Tracing distribuído (OpenTelemetry)

**`src/core/tracing.py`** (novo), API exata:
- `ALLOWED_ATTRIBUTES: frozenset[str]` = `app.trace_id`, `user.hash`, `service.replica`, `http.route`, `http.status_code`,
  `graph.node`, `llm.caller`, `llm.model`, `llm.input_tokens`, `llm.output_tokens`, `llm.fallback_used`, `llm.status`,
  `tool.name`, `tool.status`, `agent.name`, `ticket.id`, `ticket.status`, `ticket.priority`, `guardrail.decision`,
  `answer_check.status`, `notification.status`, `rate_limit.backend`. Qualquer outra chave é descartada.
- `configure_tracing(exporter: SpanExporter | None = None, *, simple: bool = False) -> TracerProvider` — cria um
  `TracerProvider` próprio do módulo (NÃO use `trace.set_tracer_provider`), com `Resource` (`service.name` =
  `OTEL_SERVICE_NAME`, `service.instance.id` = `REPLICA_NAME` ou hostname, `deployment.environment` = `APP_ENV`). Com
  `exporter`: `SimpleSpanProcessor` se `simple`, senão `BatchSpanProcessor`. Sem `exporter`: pela setting
  `TRACING_EXPORTER` (`none` → nenhum processor, mas os spans continuam tendo ids; `console` → `ConsoleSpanExporter`;
  `otlp` → `OTLPSpanExporter(endpoint=OTEL_EXPORTER_OTLP_ENDPOINT + "/v1/traces")`). Chamar de novo substitui o provider.
- `ensure_tracing() -> TracerProvider` — chama `configure_tracing()` só se ainda não houver provider (é o que o `lifespan`
  usa, para não desfazer o provider que um teste configurou).
- `span(name: str, attributes: dict | None = None, context=None)` — context manager que abre um span corrente (filho do
  corrente, ou de `context` se dado), filtra os atributos pela allowlist e, em exceção, marca
  `Status(StatusCode.ERROR, type(exc).__name__)` e relança. **Nunca** `record_exception` nem a mensagem da exceção.
- `set_attributes(attrs: dict) -> None` (no span corrente, filtrado), `extract_context(headers) ` e
  `inject_traceparent(headers: dict) -> None` com `TraceContextTextMapPropagator`, `current_trace_id() -> str | None`
  (32 hex do span corrente; `None` se inválido) e `shutdown_tracing()`.
